Docker — Build & Check

Các câu lệnh chính cho TravelHub trên Ubuntu WSL2 / Docker Compose. Mở file HTML này bằng Chrome hoặc Edge, không cần Internet để xem. Nhấn Sao chép để lấy lệnh. Bản cập nhật: xem URL Cloudflare vừa tạo và dừng/kill các container an toàn.

0. Vào thư mục dự án

cd /mnt/c/Users/Khanh/Desktop/ANY/travelhub-copilot-docs

Mở Ubuntu WSL, sau đó chạy các lệnh bên dưới tại thư mục này. Cần có .env hợp lệ và Docker đang hoạt động.

LOCAL — LẬP TRÌNH

1. Build & chạy Local

Chạy Vue User/Admin bằng Vite dev server và FastAPI để phát triển trên máy.

Build + Start + Check

docker compose up -d --build
docker compose ps
curl -i http://127.0.0.1:8000/health
Ứng dụngĐịa chỉ mở trên máy PC
Website Userhttp://localhost:5173
Website Adminhttp://localhost:5174
Backendhttp://localhost:8000/health

Các địa chỉ localhost chỉ dùng trên chính máy chạy Docker, không tự truy cập được qua 4G.

PUBLIC — DEMO TỪ THIẾT BỊ KHÁC

2. Build & kiểm tra bản Public

Build Vue User/Admin thành file tĩnh phục vụ qua Nginx, API đi qua cùng origin. Không mở Vite dev server ra Internet.

Trước khi chuyển sang cấu hình Public, sao lưu PostgreSQL, kiểm tra JWT_SECRET_KEY đủ mạnh và chỉ dùng dữ liệu demo. Compose Public có thể khởi động lại backend.

Validate cấu hình

docker compose -f docker-compose.yml -f docker-compose.pc-tunnel.yml config --quiet

Build + Start + Check

docker compose -f docker-compose.yml -f docker-compose.pc-tunnel.yml up -d --build backend public-web admin-web
docker compose -f docker-compose.yml -f docker-compose.pc-tunnel.yml ps

Kiểm tra User HTML

docker compose -f docker-compose.yml -f docker-compose.pc-tunnel.yml exec public-web wget -qO- http://127.0.0.1:8080/ | head -c 200

Kiểm tra Admin HTML

docker compose -f docker-compose.yml -f docker-compose.pc-tunnel.yml exec admin-web wget -qO- http://127.0.0.1:8081/ | head -c 200

Kiểm tra API qua Nginx

docker compose -f docker-compose.yml -f docker-compose.pc-tunnel.yml exec public-web wget -qO- http://127.0.0.1:8080/api/v1/tours | head -c 300
Kết quả mong đợi: hai trang HTML có <!doctype html>, API trả JSON chứa "items". Đây mới là build/check nội bộ, chưa có URL công khai.
CLOUDFLARE — HTTPS + OTP

3. Truy cập Public trên điện thoại / laptop khác

Sau khi bước 2 thành công, mở hai terminal Ubuntu riêng và chạy Quick Tunnel. Cloudflare cấp hai URL ngẫu nhiên *.trycloudflare.com, không cần mua domain.

Terminal A — Website User

set -o pipefail
docker compose -f docker-compose.yml -f docker-compose.pc-tunnel.yml run --rm --no-deps -e TUNNEL_TOKEN= cloudflared tunnel --url http://public-web:8080 --allowed-mail nguyenquockhanh16032k@gmail.com 2>&1 | tee /tmp/travelhub-user-tunnel.log

Terminal B — Website Admin

set -o pipefail
docker compose -f docker-compose.yml -f docker-compose.pc-tunnel.yml run --rm --no-deps -e TUNNEL_TOKEN= cloudflared tunnel --url http://admin-web:8081 --allowed-mail nguyenquockhanh16032k@gmail.com 2>&1 | tee /tmp/travelhub-admin-tunnel.log
BẮT BUỘC xác minh trang yêu cầu OTP với email được phép trước khi chia sẻ URL. Nếu --allowed-mail không được hỗ trợ hoặc trang mở ngay không cần OTP, nhấn Ctrl + C để dừng Tunnel; không bỏ lớp bảo vệ để public Admin. OTP Cloudflare không tự cấp role SUPER_ADMIN trong TravelHub.

Trên điện thoại, tắt Wi-Fi, mở URL do terminal in ra bằng 4G/5G để thử. Giữ PC, Docker và terminal đang chạy. URL có thể thay đổi sau mỗi lần tạo Tunnel.

XEM URL PUBLIC ĐƯỢC CẤP

4. Xem URL Cloudflare đã tạo & kiểm tra từ thiết bị khác

Quick Tunnel in URL ngay trong Terminal A/B. Hai lệnh bên trên đã lưu thêm log bằng tee, nên bạn có thể mở Terminal C mới để đọc URL. Không cần Cloudflare Dashboard, không cần tên miền riêng.

Xem URL website User

grep -Eo 'https://[a-zA-Z0-9-]+\.trycloudflare\.com' /tmp/travelhub-user-tunnel.log | tail -1

Xem URL Admin

grep -Eo 'https://[a-zA-Z0-9-]+\.trycloudflare\.com' /tmp/travelhub-admin-tunnel.log | tail -1
Chỉ dùng lệnh grep nếu bạn đã khởi động tunnel bằng lệnh có | tee /tmp/... như phần 3. Nếu trước đó chạy lệnh cũ (không có tee), xem trực tiếp URL trong terminal đang chạy; đừng kỳ vọng file log tự xuất hiện. Không phải mọi thông báo PASS đều có nghĩa URL đã được cấp.

Kiểm tra URL public bằng curl

Chạy trong WSL; thay URL mẫu bằng URL thật vừa lấy. Nếu Cloudflare yêu cầu OTP, mã HTTP 302/401/403 có thể là phản hồi xác thực bình thường, không phải website hỏng. Không tự động bỏ OTP để lấy HTTP 200.

curl -IL --max-time 20 https://TEN-THAT.trycloudflare.com

Dán URL thực tế để mở nhanh

HTML này là hướng dẫn tĩnh chạy offline: không tự quét Docker hoặc lấy URL, bạn dán URL từ terminal vào đây để mở.

Kiểm tra đúng: trên điện thoại tắt Wi-Fi, mở URL qua 4G/5G; phải thấy bước xác minh Cloudflare bằng email được phép trước khi thấy TravelHub. Sau OTP, Admin vẫn cần tài khoản TravelHub có quyền phù hợp.
DỪNG / KILL KHÔNG MẤT DỮ LIỆU

5. Dừng Quick Tunnel hoặc Docker

Dừng URL Public ngay (ưu tiên)

Trong Terminal A và Terminal B, nhấn Ctrl + C để dừng hai Quick Tunnel. Các URL public sẽ ngừng hoạt động. Lệnh có tee vẫn dừng bằng Ctrl + C.

Kiểm tra container cloudflared nào đang chạy

docker ps --filter label=com.docker.compose.service=cloudflared --format 'table {{.ID}}\t{{.Names}}\t{{.Status}}'

Nếu Terminal A/B đã đóng mà còn container cloudflared chạy, kiểm tra đúng container Quick Tunnel bằng tên/ID rồi dừng container đó theo lệnh dưới. Không dừng nhầm named tunnel nếu bạn còn dùng.

docker stop ID_CONTAINER_CAN_DUNG

Dừng User/Admin Public Nginx (giữ Backend & Database)

docker compose -f docker-compose.yml -f docker-compose.pc-tunnel.yml stop public-web admin-web

Dừng Local (giữ database)

docker compose stop user admin

Dừng tất cả container TravelHub (không xóa volume)

docker compose -f docker-compose.yml -f docker-compose.pc-tunnel.yml stop
Lệnh stop không xóa PostgreSQL volume. TUYỆT ĐỐI không dùng docker compose down -v khi cần giữ database. Nếu muốn chỉ tắt public nhưng vẫn dev local, dùng Ctrl + C để dừng các tunnel thay vì dừng backend.

6. Khi lỗi / kiểm tra log

Xem log

docker compose -f docker-compose.yml -f docker-compose.pc-tunnel.yml logs --tail=80 backend public-web admin-web

Khi có lỗi 500 từ API, xem backend logs và kiểm tra Alembic. Khi URL tunnel không xuất hiện, xem log terminal A/B, DNS và kết nối Internet.
